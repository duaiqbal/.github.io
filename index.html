About

I learn by building, not by memorizing slides. Every project on this page started as a gap in my own understanding — I didn't know how translation APIs worked end to end, so I built one, from folder structure to UI to version control.

I work independently by habit, not just by circumstance: designing, testing, and iterating on models without formal supervision, and closing knowledge gaps through deliberate, self-directed research. I hold myself to one standard — finish it, and understand it well enough to explain it to someone else.

How I Work

Principle 01

Architecture before code

Every project starts as a plan — modular structure, clear file responsibilities — before a single feature gets built.

Principle 02

Data before assumptions

Preprocessing, feature selection, and parameter tuning come before I trust a model's output.

Principle 03

Iterate, don't guess

I test, measure, and tune rather than assume a first version is the right one.

Principle 04

Understand it, then explain it

If I can't explain a concept simply — like cloud computing in one image and a paragraph — I don't understand it yet.
